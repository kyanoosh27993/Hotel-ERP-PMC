## ۰. خلاصه اجرایی

برنامهٔ Hotel ERP اکنون یک شل وب SPA دارد (۱۶ ماژول عملیاتی، API نست‌جی‌اس، ۲۸ تست e2e سبز) اما **ورود» ندارد و چیدمان آن با نرم‌افزار مرجع «آسا» تفاوت کامل دارد. این پلان، بازطراحی سه لایهٔ رابط را تعریف می‌کند — دقیقاً بر اساس استخراج کد از فایل‌های پیوست کاربر، نه حدس:

1. **صفحهٔ ورود** — مودال ورود آسا با کپچای تصویری، همهٔ پیام‌های خطای آن، «آخرین ورود»، و لوگوی برنامه.
2. **صفحهٔ اصلی** — گرید سه‌دسته‌ایِ ۲۱ ماژول آسا با همان آیکن‌ها، انیمیشن hover سه‌بعدیِ همان فایل، نوار کاربر (عکس + نام + سمت)، تاریخ/ساعت شمسی.
3. **بخش پذیرش** — شلِ صفحهٔ پذیرش آسا (منوی آیکنی عمودی، نوار ابزار، علاقه‌مندی‌ها، جستجو، تم‌ها) + پیاده‌سازی فازبندی‌شدهٔ قابلیت‌های PMS مطابق بخش 7.1 نقشه‌راه خودِ کاربر.

اصل حاکم بر اجرا: **فاز به فاز، هر فاز با خروجی قابل تست و کامیت جداگانه؛ بدون پاشیدن کد به چند ماژول نیمه‌کاره.**

### ۱.۴ انیمیشن hover — کد واقعی آسا (از `style2.php`)

انیمیشن امضای آسا یک چرخش سه‌بعدیِ flip است:

```css
/* استخراج‌شده از style2.php آسا */
transition: all 0.45s ease-in-out;            /* رویداد اصلی */
transition: all 0.15s ease-in-out;            /* بازگشت سریع */
transition: all 0.45s ease-in-out 0.85s;      /* با تأخیر — ورود پله‌ای */
transform: rotateY(-80deg) → rotateY(0deg);   /* flip سه‌بعدی روی محور Y */
transform: scale(0.8) → scale(0.9) → scale(1);/* بزرگ‌شدن پله‌ای */
transform: translate(0,0) → translate(50px,50px) → translate(-50px,-20px) rotate(30deg);
transform-origin: left top / left center;
```

پیاده‌سازی در برنامهٔ ما: همان مقادیر دقیق (dur/curve/delay) با کلاس‌های `asa-flip` روی کاشی‌ها؛ شامل حالت فوکus با کیبورد (`menu_li_hover` از `dynamicFindMenu.js` آسا) برای دسترس‌پذیری.

## ۵. فازبندی تفصیلی بخش پذیرش (مطابق بخش 7.1 نقشه‌راه کاربر)

**۵ بخش مهم و کاربری که در صفحه اصلی/شل پذیرش اول از همه نشان داده می‌شوند** (انتخاب بر اساس آیکن‌های toolbar آسا + قابلیت‌های 7.1):

1. **Room Rack — نقشهٔ زندهٔ اتاق‌ها** (`room_rack`) — وضعیت اشغال/تمیز/تعمیر، رنگ‌بندی، کلیک=جزئیات اقامت.
2. **پذیرش و Check-in** — ثبت مهمان + اسناد + تخصیص اتاق با کنترل هم‌زمانی (قاعدهٔ 7.1: رزرو/تخصیص/اقامت سه مفهوم مستقل).
3. **حساب مهمان (Folio)** (`bill`) — شارژ خدمات، پیش‌پرداخت، ودیعه، Split/Merge.
4. **تسویه و Check-out** (`cash_new`) — اتصال به صندوق/خزانه؛ سند مالی.
5. **رزرو و ظرفیت** (`reservation`) — تقویم رزرو، نرخ، جلوگیری از overbooking.

**فازهای اجرای عملیاتی پذیرش:**

| فاز | محتوا | موجودیت‌های DB | APIها | معیار پایان |
|---|---|---|---|---|

## ۶. امنیت صفحهٔ ورود (مپ خطاهای آسا → پیاده‌سازی ما)

| پیام آسا | پیاده‌سازی ما |
|---|---|
| نام کاربری و رمز مطابقت ندارند | 401 با کد `BAD_CREDENTIALS` |
| حروف امنیتی مطابقت ندارند | 400 با کد `CAPTCHA_MISMATCH` + کپچای جدید |
| اجازه ورود با این IP را ندارید | 403 با کد `IP_BLOCKED` (جدول blacklist) |
| این نام کاربری در سیستم لاگین است | 409 با کد `ALREADY_LOGGED_IN` (قابل سیاست: اجبار خروج) |
| اعتبار حساب به پایان رسیده است | 402 با کد `EXPIRED` |
| حساب مسدود است | 423 با کد `DEACTIVATED` |
| دسترسی مسدود (blacklist) | 403 با کد `USER_BLACKLISTED` |
| حساسیت حروف | مقایسه case-sensitive در همهٔ مراحل |
| قفل پس از تلاش | ۵ خطا → قفل ۱۵ دقیقه + ثبت در audit log |

## ۷. ریسک‌ها و وابستگی‌ها

1. **فایل‌های بعدی آسا** — برای «تب‌های دقیق پذیرش» و فرم‌های داخلی هر بخش، کارفرما هر صفحه را جداگانه می‌فرستد؛ هر فایل = یک زیرفاز مشخص. (روال توافق‌شدهٔ بند ۷)
2. **مجوز آیکن‌ها** — آیکن‌ها از پکیج مرجع کارفرما استخراج شده و در ریپوی خصوصی خودش نگهداری می‌شوند؛ پیش از انتشار عمومی باید مجوز استفاده بررسی شود.
3. **حجم EXE/APK** — افزودن آیکن‌ها/فونت به شل وب حجم باندل را ~کمتر از ۱MB بالا می‌برد؛ در بازسازی بعدی EXE/APK کنترل می‌شود.
4. **MFA** — در نسخهٔ دسکتاپ خاموش است (تصمیم قبلی)؛ صفحهٔ ورود میدان MFA را فقط برای نقش‌های فعال نشان می‌دهد.
5. **RTL/فونت** — شل فعلی RTL فارسی است؛ فونت‌های آسا (Vazir) در شل موجود است و همان استفاده می‌شود.
