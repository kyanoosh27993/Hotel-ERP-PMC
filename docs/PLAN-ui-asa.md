## ۰. خلاصه اجرایی

برنامهٔ Hotel ERP اکنون یک شل وب SPA دارد (۱۶ ماژول عملیاتی، API نست‌جی‌اس، ۲۸ تست e2e سبز) اما **ورود» ندارد و چیدمان آن با نرم‌افزار مرجع «آسا» تفاوت کامل دارد. این پلان، بازطراحی سه لایهٔ رابط را تعریف می‌کند — دقیقاً بر اساس استخراج کد از فایل‌های پیوست کاربر، نه حدس:

1. **صفحهٔ ورود** — مودال ورود آسا با کپچای تصویری، همهٔ پیام‌های خطای آن، «آخرین ورود»، و لوگوی برنامه.
2. **صفحهٔ اصلی** — گرید سه‌دسته‌ایِ ۲۱ ماژول آسا با همان آیکن‌ها، انیمیشن hover سه‌بعدیِ همان فایل، نوار کاربر (عکس + نام + سمت)، تاریخ/ساعت شمسی.
3. **بخش پذیرش** — شلِ صفحهٔ پذیرش آسا (منوی آیکنی عمودی، نوار ابزار، علاقه‌مندی‌ها، جستجو، تم‌ها) + پیاده‌سازی فازبندی‌شدهٔ قابلیت‌های PMS مطابق بخش 7.1 نقشه‌راه خودِ کاربر.

اصل حاکم بر اجرا: **فاز به فاز، هر فاز با خروجی قابل تست و کامیت جداگانه؛ بدون پاشیدن کد به چند ماژول نیمه‌کاره.**

### ۱.۴ انیمیشن hover — کد واقعی آسا (از `style2.php`)

انیمیشن امضای آسا یک چرخش سه‌بعدیِ flip است:

```css
/* استخراج‌شده از style2.php آسا */
transition: all 0.45s ease-in-out;            /* رویداد اصلی */
transition: all 0.15s ease-in-out;            /* بازگشت سریع */
transition: all 0.45s ease-in-out 0.85s;      /* با تأخیر — ورود پله‌ای */
transform: rotateY(-80deg) → rotateY(0deg);   /* flip سه‌بعدی روی محور Y */
transform: scale(0.8) → scale(0.9) → scale(1);/* بزرگ‌شدن پله‌ای */
transform: translate(0,0) → translate(50px,50px) → translate(-50px,-20px) rotate(30deg);
transform-origin: left top / left center;
```

پیاده‌سازی در برنامهٔ ما: همان مقادیر دقیق (dur/curve/delay) با کلاس‌های `asa-flip` روی کاشی‌ها؛ شامل حالت فوکus با کیبورد (`menu_li_hover` از `dynamicFindMenu.js` آسا) برای دسترس‌پذیری.

## ۵. فازبندی تفصیلی بخش پذیرش (مطابق بخش 7.1 نقشه‌راه کاربر)

**۵ بخش مهم و کاربری که در صفحه اصلی/شل پذیرش اول از همه نشان داده می‌شوند** (انتخاب بر اساس آیکن‌های toolbar آسا + قابلیت‌های 7.1):

1. **Room Rack — نقشهٔ زندهٔ اتاق‌ها** (`room_rack`) — وضعیت اشغال/تمیز/تعمیر، رنگ‌بندی، کلیک=جزئیات اقامت.
2. **پذیرش و Check-in** — ثبت مهمان + اسناد + تخصیص اتاق با کنترل هم‌زمانی (قاعدهٔ 7.1: رزرو/تخصیص/اقامت سه مفهوم مستقل).
3. **حساب مهمان (Folio)** (`bill`) — شارژ خدمات، پیش‌پرداخت، ودیعه، Split/Merge.
4. **تسویه و Check-out** (`cash_new`) — اتصال به صندوق/خزانه؛ سند مالی.
5. **رزرو و ظرفیت** (`reservation`) — تقویم رزرو، نرخ، جلوگیری از overbooking.

**فازهای اجرای عملیاتی پذیرش:**

| فاز | محتوا | موجودیت‌های DB | APIها | معیار پایان |
|---|---|---|---|---|

## ۷. ریسک‌ها و وابستگی‌ها

1. **فایل‌های بعدی آسا** — برای «تب‌های دقیق پذیرش» و فرم‌های داخلی هر بخش، کارفرما هر صفحه را جداگانه می‌فرستد؛ هر فایل = یک زیرفاز مشخص. (روال توافق‌شدهٔ بند ۷)
2. **مجوز آیکن‌ها** — آیکن‌ها از پکیج مرجع کارفرما استخراج شده و در ریپوی خصوصی خودش نگهداری می‌شوند؛ پیش از انتشار عمومی باید مجوز استفاده بررسی شود.
3. **حجم EXE/APK** — افزودن آیکن‌ها/فونت به شل وب حجم باندل را ~کمتر از ۱MB بالا می‌برد؛ در بازسازی بعدی EXE/APK کنترل می‌شود.
4. **MFA** — در نسخهٔ دسکتاپ خاموش است (تصمیم قبلی)؛ صفحهٔ ورود میدان MFA را فقط برای نقش‌های فعال نشان می‌دهد.
5. **RTL/فونت** — شل فعلی RTL فارسی است؛ فونت‌های آسا (Vazir) در شل موجود است و همان استفاده می‌شود.

### API (NestJS)
- `GET /api/v1/auth/captcha` — کپچای SVG سمت سرور (`captcha.service.ts`): کد ۵ نویسهٔ بدون نویسهٔ گنگ، یک‌بارمصرف، TTL ۵ دقیقه، هش SHA-256، خطوط/نقاط نویز، throttle 30/min.
- `POST /auth/login` اکنون `captchaId` + `captchaText` می‌پذیرد؛ بدون کپچای معتبر → `CAPTCHA_MISMATCH` (پیام دقیق آسا).
- قفل‌شدگی: ۵ تلاش ناموفق → قفل ۱۵ دقیقه → پیام «دسترسی شما … مسدود شده است»؛ ریست شمارنده فقط پس از انقضای قفل (باگ شمارنده در تست کشف و اصلاح شد).
- `User` جدید: `photoUrl`، `position`، `lastLoginAt`، `lastLoginIp` (migration: `20261202000000_user_profile_fields`)؛ پاسخ login اکنون `fullName/photoUrl/position + lastLogin` (کادر «اطلاعات آخرین ورود») می‌دهد؛ `GET /auth/me` هم پروفایل کامل می‌دهد.
- کلید env `AUTH_CAPTCHA_REQUIRED=false` فقط برای e2e/تست‌ها — در تولید پیش‌فرض روشن.
- تست‌ها: **۴۷ واحد سبز** (۴ تست جدید: کپچا ×3، قفل‌شدگی ×1) + build سبز؛ سه اسپک e2e با فلگ خاموش‌کردن کپچا پچ شدند.

### وب (شل فعلی، بدون فریم‌ورک جدید)

- `4.zip` = دو صفحهٔ واقعی آسا: «لیست صورتحسابهای باز مهمان» (Open Invoices Guests List) + «ثبت اقلام اضافی اتاق» (Room Additional Items) → کپی به `docs/reference/asa/pages/4/` — بدنهٔ این دو صفحه با AJAX لود می‌شده؛ طراحی بر اساس عنوان/الگوی آسا ساخته شد.

### نیاز ۱ — مدیریت خودی طبقات/اتاق‌ها/نوع‌ها/نرخ‌ها
- API جدید: `GET/POST/PATCH /pms/room-types`، `POST /pms/rooms`، `PATCH /pms/rooms/:id` (کد/طبقه/نوع)، `DELETE /pms/rooms/:id` (فقط بدون سابقهٔ اقامت؛ اتاق اشغال رد می‌شود) — مجوز ROOM_UPDATE.
- ماژول وب `rooms-setup.js` (روی سایدبار «تنظیم اتاق‌ها» + دکمهٔ ⚙ در تولبار روم‌رک): جدول انواع با ویرایش inline نام/ظرفیت/نرخ، فرم نوع جدید، جدول اتاق‌ها با ویرایش inline کد/طبقه/نوع، بستن/حذف، فرم اتاق جدید. هر تغییر بلافاصله در روم‌رک (rooms/map) دیده می‌شود.
- تست واقعی: نوع «سوئیت یک خوابه ۳ تخته» با نرخ ۶.۵M ساخته شد، اتاق ۴۰۱ طبقهٔ ۴ ساخته شد، نرخ به ۷M ویرایش شد → در روم‌رک ظاهر شد ✓

### نیاز ۲ — چیدمان دلخواه روم‌رک
- select «گروه‌بندی: طبقه / نوع اتاق» + چیدمان ستونی/جریانی در روم‌رک. گروه‌بندی نوع: هر نوع اتاق یک ستون با عنوان فارسی‌اش (تویین‌ها زیر هم، دبل‌ها زیر هم، سوئیت‌ها زیر هم…). تست واقعی با دو نوع ✓

### نیاز ۳ — تفکیک و گزارش ایرانی/خارجی
- schema: `Reservation.nationality` (IRANIAN | FOREIGNER) + مهاجرت `20261124130000_nationality_folio_items`.
- API: `POST /pms/reservations` فیلد ملیت می‌پذیرد؛ `GET /pms/reservations` پارامترهای `from/to/nationality` + خروجی ملیت.
- فرم رجیستر: select «ملت» (ایرانی/خارجی).
- ماژول `guestreport.js` در تب «گزارشات روزانه» پذیرش: بازهٔ شمسی + وضعیت → جدول تعداد مهمان/اتاق گرفته‌شده/جمع شب‌ها به تفکیک ایرانی/خارجی + فهرست تفصیلی. بدون سرور از رجیسترهای محلی.
- تست واقعی: رزرو ایرانی ثبت شد → گزارش: ایرانی ۱ مهمان/۱ اتاق/۷ شب ✓ (DB: nationality=IRANIAN)
- یافتهٔ مهم: کنترل ظرفیت واقعی رزرو (فاز ۴) — نوع بدون اتاق → «Room type capacity exhausted» ✓

### نیاز ۴ — اسکن مدارک در رجیستر
- بخش «اسکن مدارک شناسایی» در فرم رجیستر: سه دکمهٔ دوربین/فایل (کارت ملی، شناسنامه، پاسپورت) → فشرده‌سازی canvas (max 1400px، jpeg 0.72) → ذخیرهٔ IndexedDB (`hotel-erp-docs`) → فهرست با thumbnail، پرینت (پنجرهٔ چاپ با تصویر + سربرگ مهمان) و حذف. کاملاً آفلاین کار می‌کند.
- تست واقعی: تصویر آزمایشی → ذخیره شد + thumbnail + چاپ ✓

### R4 — فولیو (بر اساس 4.zip)
- مدل `FolioItem` (stayId/desc/qty/unitRials/totalRials/postedAt) + `POST /pms/stays/:id/folio-items` (وضعیت OPEN الزامی؛ folioRials += total در تراکنش) + `GET /pms/stays/:id/folio-items` + `GET /pms/folios/open`.
- ماژول `folio.js` در تب «عملیات» پذیرش: پنل «ثبت اقلام اضافی اتاق» با کاتالوگ ۱۰ قلم پیش‌فرض + پنل «لیست صورتحساب‌های باز مهمان» (اتاق/مهمان/ورود/خروج/اقلام/جمع) + expand اقلام + پرینت فاکتور (سربرگ + جمع + امضا) + «تسویه و خروج» → POST check-out واقعی.
- تست واقعی: شام×۲ به فولیو اقامت STY-2026-000001 → جمع ۵۰۰٬۰۰۰ ✓ → فاکتور چاپ درست ✓ → تسویه/چک‌اوت → اتاق ۴۰۱ بنفش (کثیف) در روم‌رک ✓

### راستی‌آزمایی کامل (API واقعی + PG embedded روی 5433)
- ورود واقعی admin با کپچای سرور (خواندن تصویر SVG) — MFA نقش‌محور: برای تست محلی `roles.sensitiveMfa=false` شد (فقط DB تست؛ کد دست‌نخورده).
- نکته: seed رمز پیش‌فرض `ChangeMe_Str0ng!` است (متغیر SEED_ADMIN_PASSWORD)؛ مستند INSTALL-WINDOWS رمزهای دسکتاپ جداگانه دارد.
- همهٔ ۸ قابلیت بالا با مرورگر به‌صورت کاربر واقعی اجرا و تأیید شد.
