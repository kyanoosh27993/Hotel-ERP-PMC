# Runbook بازیابی در شرایط بحران (Disaster Recovery) — F1-T8

> معیار پذیرش فاز ۱: بازیابی کامل زیر ۴ ساعت (آزمون‌شده در CI به‌صورت round-trip).

## سناریوها

| سناریو | اقدام | هدف زمانی |
|---|---|---|
| حذف اشتباه جدول/داده | restore از آخرین بکاپ رمزشده | ۳۰ دقیقه |
| خرابی کامل سرور | سرور جدید + restore + تغییر DNS | ۴ ساعت |
| فاجعه منطقه‌ای (اتاق سرور) | بکاپ خارج‌ازسرور (S3/NAS — راشکلون) | ۴ ساعت |

## دستور عملیات بازیابی

```bash
# ۰) توقف سرویس (تأیید دو نفره: مدیر سیستم + مدیر مالی)
docker compose stop api

# ۱) انتقال بکاپ به سرور جدید (فایل .enc + .sha256)
scp backups/hotel_erp_*.sql.gz.enc new-server:/backups/

# ۲) بازیابی (اتمیک، با ON_ERROR_STOP)
export DATABASE_URL=postgresql://hotel:***@localhost:5432/hotel_erp?schema=public
export BACKUP_PASSPHRASE=***   # هرگز در خط فرمان history نماند
infrastructure/backup/restore.sh /backups/hotel_erp_<STAMP>.sql.gz.enc

# ۳) بالا آوردن مجدد و صحت‌سنجی
docker compose up -d
curl -s localhost:3000/api/v1/health   # {"status":"ok","db":"up"}
# ۴) نمونه‌های صحت‌سنجی داده:
#    تعداد رزرو امروز، آخرین سند حسابداری، تراز آزمون یک روز مشخص
```

## قواعد بکاپ

- روزانه ساعت ۰۲:۰۰ (cron) + پیش از هر تغییر اسکیمای مهم — `infrastructure/backup/backup.sh`
- رمزگذاری AES-256-CBC (PBKDF2 ۲۰۰هزار دور) — کلید در مدیریت‌گذرواژه سازمانی، **هرگز در سرور بکاپ‌گیری**
- نگهداری ۳۰ روز + ماهانه یک نسخه تا یک سال (پارامتر BACKUP_KEEP_DAYS)
- صحت‌سنجی هر بسته با gzip -t + SHA256 — بکاپ بدون تست بازیابی = بدون بکاپ
- **آزمون بازیابی فصلی** (هر فصل یک‌بار روی محیط تست) با ثبت در جدول زیر:

| تاریخ آزمون | نتیجه | زمان بازیابی | مهر تأیید |
|---|---|---|---|
| 【پس از اولین آزمون فصلی تکمیل شود】 | | | |
