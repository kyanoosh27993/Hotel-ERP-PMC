# خلاصهٔ فاز ۱۳ (شروع) — امنیت، بار، بازیابی، آفلاین — نسخهٔ ۰.۱۲ (موج ۶)

تاریخ اجرا: ۱۴۰۵/۰۹/۰۳ (۲۰۲۶-۱۱-۲۴) — محیط: سندباکس Linux (postgres جاسازی‌شده ۱۷)

## F13-T2 — آزمون امنیت (ASVS سطح ۲ — بخش‌های قابل اجرا در سندباکس)

| بررسی | روش | نتیجه |
|---|---|---|
| هدرهای امنیتی | `curl -I` | ❌ نبود → ✅ **اصلاح شد**: X-Content-Type-Options=nosniff، X-Frame-Options=DENY، Referrer-Policy=no-referrer، Permissions-Policy (کد در `main.ts`) |
| Brute-force ورود | ۱۸ تلاش رمز نادرست | ۱۵×۴۰۱ سپس **429 TOO_MANY_ATTEMPTS** (پنجرهٔ ۶۰ ثانیه، per-IP) ✓ |
| TTL توکن | ورود زنده | ۹۰۰ ثانیه؛ منقضی → پیام واضح + ورود مجدد ✓ |
| MFA | ورود admin/accountant بدون TOTP | MFA_REQUIRED → با TOTP معتبر فقط ✓ |
| SQL Injection | `?query=' OR 1=1--` و `'; DROP TABLE rooms;--` | ۴۰۴ بدون نشت خطای SQL؛ DB سالم (Prisma پارامتری) ✓ |
| XSS | payload در guestName (`<script>`، `<img onerror>`) | ذخیره شد ولی شل با `textContent` رندر می‌کند — **اجرا نشد** ✓ |
| Secret-scan | git grep الگوهای کلید/توکن | هیچ راز هاردکد در سورس ✓ |
| RBAC منفی | ۱۵ تست ماژول + بار با نقش غلط | 403 درست برای مسیرهای غیرمجاز ✓ |
| npm audit | `npm audit fix` | آسیب‌پذیری‌های semver-safe رفع شد؛ باقی‌مانده transitive وابستگی dev (body-parser/js-yaml/lodash در زنجیرهٔ Nest/webpack) — ریسک قابل‌قبول dev، در استقرار تولیدی با pinned نسخه‌ها پایش می‌شود |

## F13-T6 — بازیابی از فاجعه (DR)

- بکاپ فیزیکی کامل pgdata (۷۰MB) → **تخریب کامل** `/tmp/hotel-pgdata` → بازیابی → اجرای مجدد.
- صحت: ۱۵ اتاق، ۸ کاربر، ۲۰ سند حسابداری، ۱۷ مهاجرت — همه سالم؛ API روی 0.12.0 بدون خطا بالا آمد.
- زمان بازیابی: چند ثانیه (سقف سند: ۴ ساعت) ✓. مکانیزم توصیه‌شدهٔ تولید: `BACKUP_DIR` + passphrase (F1-T8) روی ماشین پایلوت روزانه زمان‌بندی می‌شود.

## F13-T5 — ادامهٔ عملیات حیاتی بدون شبکه

- **معماری دسکتاپ (EXE/AppImage)**: API+DB روی همان دستگاه — قطع اینترنتِ هتل، عملیات پذیرش/صندوق/انبار را متوقف نمی‌کند (همان استدلال F6-T6 برای PDA آفلاین انبار).
- **وب شبکه‌ای**: قطع سرور، شل را هم از دست می‌دهد (شل از API سرو می‌شود) — رفتار: فرم‌ها پیام «عدم اتصال» می‌دهند، کرش ندارند؛ محدودیت مستند و در پایلوت با نسخهٔ دسکتاپ حل می‌شود.
