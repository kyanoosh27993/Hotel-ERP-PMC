# فاز ۹ — F9-T5: مالیات مستقیم — برنامهٔ عملکرد، اظهارنامه، شناسهٔ طرف‌های معامله

> وضعیت: اجرا شد (موج ۳ — پایان تسک‌های مالیاتی). وابستگی‌ها: کتابخانهٔ قوانین F9-T1 ✅،
> مؤدیان F9-T2 ✅، ارزش افزوده F9-T3 ✅، معاملات فصلی F9-T4 ✅، گردش کار F8-T6 ✅.
> قرارداد: §3 قانون مالیات‌های مستقیم (معافیت حقوق ۱۴۰۵: ماهانه ۴۰۰٬۰۰۰٬۰۰۰ ریال /
> سالانه ۴٬۸۰۰٬۰۰۰٬۰۰۰؛ مادهٔ ۹۱، ۱۰۵، ۱۶۹) + قاعدهٔ طلایی «ارسال مالیاتی هرگز بدون تأیید انسانی».

## ۱) برنامهٔ عملکرد — `DirectTaxPlan`
سال مالیاتی شمسی (یکتا) + محتوای JSON (ظرفیت اتاق، نرخ اشغال هدف، درآمد هدف به تفکیک بخش،
اشتغال). چرخه: DRAFT → (ذخیره/ویرایش آزاد) → CONFIRMED (تأیید حسابدار + audit). ویرایش
برنامهٔ تأییدشده → ۴۰۹؛ اصلاح فقط با بازگشایی admin. اظهارنامه بدون برنامهٔ تأییدشده
ارسال نمی‌شود (پیوند کامل‌بودن داده).

## ۲) اظهارنامهٔ مالیات عملکرد — `DirectTaxReturn`
از **اسناد قطعی سال** محاسبه می‌شود (نه تخمین):
- جمع درآمد = بستانکار ۴۱۰۱/۴۱۰۲/۴۱۰۳ در بازهٔ سال شمسی (برگرفته از quarterRange F9-T4)
- جمع هزینه‌های قابل قبول = بدهکار ۵۱۰۱..۵۱۰۴، ۵۲۰۱
- درآمد مشمول = max(0، درآمد − هزینه)
- نرخ = پارامتریک از کتابخانهٔ قوانین `LAW-DIRECT-TAX-RATE` (مادهٔ ۱۰۵ — ۲۵٪ اشخاص حقوقی؛
  معافیت‌ها و پله‌های اشخاص حقیقی در params با مارکر «نیازمند تأیید بخشنامهٔ ۱۴۰۵»)
- مالیات متعلق = مشمول × نرخ؛ پیش‌پرداخت = بستانکار ۲۲۰۳ (مالیات حقوق کسرشدهٔ سال)؛
  قابل پرداخت = max(0، متعلق − پیش‌پرداخت)
- linesJson = تفکیک هر حساب → «رد پای محاسبه» برای کنترل دفاتر

چرخه: DRAFT (محاسبهٔ Idempotent) → SUBMITTED **فقط با تأیید انسانی** گردش کار
`WF-DIRECTTAX-SUBMIT` (۱ مرحله، مجوز `compliance.invoice_send`، خودتأییری ممنوع) — مصرف‌کنندهٔ
`workflow.completed`. محاسبه روی ارسال‌شده → ۴۰۹؛ بازگشایی فقط admin (workflow.manage).

## ۳) شناسهٔ طرف‌های معامله — تجمیع زندهٔ دادهٔ واقعی
از دو منبع: معاملات فصلی F9-T4 (سال انتخابی) + صورتحساب‌های ارسال‌شده/پذیرفته‌شدهٔ مؤدیان
F9-T2 (totalRials مستقیم). تجمیع به تفکیک شناسهٔ ملی/کد اقتصادی با فروش/خرید/تعداد/منبع؛
سطرهای بدون شناسه (شامل '-') پرچم «ناقص» می‌خورند و شمارشان گزارش می‌شود — «داده‌های الزامی
کامل» یعنی گزارش کامل + اعلام صریح شکاف‌ها، نه مخفی‌کردن آن‌ها.

## ۴) فایل استاندارد
`GET /compliance/directtax/export?taxYear` → CSV با BOM و سه بخش: اظهارنامه / برنامه عملکرد /
شناسهٔ طرف‌های معامله — **فقط در وضعیت SUBMITTED** (قبل از تأیید انسانی → ۴۰۹).

## ۵) مجوزها
- `compliance.directtax_view` — admin، accountant، approver
- `compliance.directtax_manage` — admin، accountant (ثبت/تأیید برنامه، محاسبه، درخواست ارسال)
- بازگشایی → workflow.manage (admin)؛ تأیید ارسال → مجوز مرحلهٔ گردش کار (`compliance.invoice_send`)

## ۶) معیار پذیرش (تست 14-directtax — ۳۲/۳۲)
1. RBAC: پذیرش ۴۰۳؛ حسابدار/تأییدکننده/مدیر طبق ماتریس.
2. برنامهٔ عملکرد: ثبت/ویرایش DRAFT، تأیید → CONFIRMED، ویرایش تأییدشده ۴۰۹.
3. ارسال بدون برنامهٔ تأییدشده → ۴۰۹.
4. محاسبه = جمع واقعی DB (درآمد/هزینه/پیش‌پرداخت ۲۲۰۳) + مالیات = مشمول × ۲۵٪ مادهٔ ۱۰۵.
5. طرف‌های معامله: سطر کامل با شناسه + سطر ناقص پرچم‌خورده.
6. ارسال: خودتأییری ۴۰۳؛ تأییدکننده → SUBMITTED با submittedBy؛ رویداد Outbox با کلید یکتا.
7. فایل قبل از تأیید ۴۰۹، بعد از تأیید ۲۰۰ با سه بخش؛ بازگشایی فقط admin؛ محاسبهٔ مجدد آزاد.

## ۷) فرض‌ها و باقی‌مانده
- قالب دقیق آپلود اظهارنامهٔ my.tax.gov.ir موقع ابلاغ سالانه کنترل می‌شود (ستون‌ها پارامتریک).
- پله‌های مالیات عملکرد اشخاص حقیقی (۱۰–۳۰٪) در params با مارکر تأیید — بنگاه هتلدار حقوقی است.
- جدول مالیات حقوق (LAW-WITHHOLDING-SALARY) هنوز مبنای ۱۴۰۴ دارد — به‌روزرسانی بخشنامهٔ ۱۴۰۵
  به موتور حقوق مربوط است، نه این فاز (فقط در params قانون جدید ثبت شد).
