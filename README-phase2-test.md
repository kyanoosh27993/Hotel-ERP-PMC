## ۳. سناریوهای تست (به‌ترتیب)

| # | سناریو | مورد انتظار |
|---|---|---|
| ۱ | `frontdesk` کارمند ثبت کند | 403 (فقط حسابدار/مدیر) |
| ۲ | حسابدار کارمند با شبای غلط ثبت کند | 400 با پیام شبا نامعتبر |
| ۳ | حسابدار کارمند + حکم پیش‌نویس ثبت کند | 201 (status=DRAFT) |
| ۴ | حسابدار حکم خودش را تأیید کند | 403 (خودتأییری ممنوع) |
| ۵ | تأییدکننده حکم را تأیید کند | 201 (APPROVED) |
| ۶ | حسابدار `POST /payroll/runs {periodCode:"1405-09"}` | ۱۱ فیش (۱۰ seed + کارمند جدید)، paramsVersion ثبت‌شده |
| ۷ | بازمحاسبه همان دوره | همان دوره (بدون دوباره‌سازی) |
| ۸ | سه لیست: `/lists/tax` ، `/lists/insurance` ، `/lists/bank` | ۱۱ سطر؛ بیمه: ۷٪+۲۳٪=۳۰٪؛ بانک: شبای معتبر |
| ۹ | حسابدار دوره را تأیید کند | 403 |
| ۱۰ | تأییدکننده دوره را تأیید کند | 201 + **سند خودکار متوازن حقوق** در `GET /journal-entries` (بدهکار ۵۱۰۲+۵۱۰۳ / بستانکار ۲۲۰۲+۲۲۰۳+۲۱۰۲، قابل ردیابی به دوره) |
| ۱۱ | بازمحاسبه دوره تأییدشده | 409 (دوره تأییدشده تغییرناپذیر) |

فرمول قراردادی در هر فیش از API قابل کنترل است: **خالص = ناخالص − بیمه کارگر (۷٪) − مالیات**.

## ۴. پارامترهای قانونی ۱۴۰۵ (شفافیت کامل)

- تأییدشده: معافیت سالانه ۴٫۸ میلیارد ریال، بیمه ۳۰٪ (۲۳+۷)، ضریب ساعتی ۷٫۳۳، اضافه‌کاری ۱٫۴، شب‌کاری ۱٫۷۵، حق مسکن ۳۰ میلیون
- پارامتریک با برچسب [نیازمند بخشنامه رسمی]: مرز پله‌های مالیاتی (پله اول = معافیت قانونی) و عائله‌مندی — کد و نسخه پارامترها (`laws-1405.1`) در هر فیش و هر دوره **snapshot** می‌شود؛ با ابلاغ بخشنامه فقط فایل params تغییر می‌کند نه فرمول‌ها.

## ۵. معماری (خلاصه فنی)
