## ۳. سناریوهای تست (به‌ترتیب)

| # | سناریو | مورد انتظار |
|---|---|---|
| ۱ | ماتریس دسترسی چهار پنل (جدول بالا) | همان نتیجه |
| ۲ | یک رزرو برای «امروز» ثبت کنید → `ceo` | درآمد روز/ماه دقیقاً = مبلغ رزرو؛ اشغال +۱ |

## ۴. داشبورد در رابط کاربری (شل استاتیک)

`apps/web/index.html` → ماژول «داشبورد مدیر AI» → بخش جدید **«پنل زنده سرور»**:
آدرس API (پیش‌فرض `http://localhost:3000/api/v1`) و توکن JWT را وارد کنید → «بارگذاری پنل‌ها». چهار گروه KPI (مدیرعامل/مالی/رستوران/خانه‌داری) با اعداد فارسی و هشدارهای معلق رندر می‌شود؛ بدون توکن/مجوز پیام راهنما می‌دهد — بخش تحلیل آفلاین قانون ۱۷ قبلی هم سر جایش است.

## ۵. جزئیات فنی مهم

- مرز «روز» و «ماه» همه KPIها **شمسی** است (toJalaali/toGregorian از هسته مشترک) — قوانین ۱۳/۱۴
- فقط اسناد **قطعی (POSTED)** در درآمد/هزینه/مانده‌ها شمرده می‌شوند؛ پیش‌نویس‌ها فقط به‌عنوان قلم معلق گزارش می‌شوند
- درآمد = بستانکار ۴۱۰۱+۴۱۰۲؛ هزینه = بدهکار ۵۱۰۱+۵۱۰۲+۵۱۰۳؛ سود ماه = درآمد−هزینه؛ جریان نقد ماه = گردش ۱۱۰۱+۱۱۰۲
- در e2e، ادعای هر عدد با «دلتای قبل/بعد» و مقایسه با جمع کوئری مستقیم پرisma کنترل شده (بدون وابستگی به داده تست‌های دیگر)
